# opti-calc

面向一般人群的多元方程组与最优化求解编辑器：用日常写法列出条件和目标，它替你算出答案。

## 这是什么？

- **定位**：纯前端的算账工具站。不是给运筹学专业人士用的建模软件，而是给「想算清一笔账但不会写方程组」的人用的编辑器。
- **解决的核心问题**：生活中的最优决策（买几份最划算、种什么收益最高、钱不够要等多久）本质上是方程组与约束优化问题，但现有工具要么要求专业知识，要么只能算单一固定场景。

## 为什么存在？

起源是一份真实的算账文档《实际有效施肥土地块数计算》——计算某款农场游戏里的施肥地块数、所需肥料时长、在钞票不足时该等多久。

手算这类问题的痛点很清楚：

- 中间步骤一多就容易错，而且错了很难发现（该文档中「等待 29.74 分钟」就是中途舍入导致的偏差，精确值是 29.75 分钟）；
- 换个数字就得从头再算一遍；
- 「买几份」这类必须取整的量，手算很容易给出买不到的答案（如 3.19 份）。

所以做一个能反复改数字、且**不做任何近似**的求解器。

## 如何安装和运行？

**前置要求**

- Node.js 24（版本钉在 `.nvmrc`；`nvm use` / `fnm use` 会自动读取）
- [vp（Vite+）](https://vite.plus) 1.3.0 —— 构建、格式化、lint、测试统一走它

```bash
# 安装 vp（Windows 见官方安装页）
curl -fsSL https://vite.plus | bash

# 安装依赖（vp 依据 lockfile 自动检测并代理 pnpm）
vp install
```

**运行**

```bash
vp dev        # 开发服务器 → http://localhost:5173/
vp test       # 运行测试（123 个）
vp check      # 格式 + lint + 类型检查
vp build      # 生产构建 → dist/
vp preview    # 预览构建产物 → http://localhost:4173/
```

国内网络建议先设镜像：`pnpm config set registry https://registry.npmmirror.com`。

## 当前状态

- **阶段**：开发中。求解内核与 E2E 验收已完成，界面可用但未做移动端适配与多模型管理。
- **已知限制**：
  - 支持**线性模型与二次项（变量相乘）**。整数 / 二元因子的乘积精确求解；连续 × 连续（如价格 × 销量）属于非凸问题，返回近似解并标注损失率上界。三次及以上相乘、变量做除数仍会被明确拒绝。
  - `!=` 约束不支持——它定义的可行域不是凸集，线性规划无法处理。
  - 实数变量上的严格不等式（`<` / `>`）会被放宽为闭区间并给出提示；整数变量则精确收紧。
  - 变量数超过 40 时跳过「解是否唯一」的探测，只给出其中一个解。
  - 整数规划搜索节点上限 20 万，超出会报告问题规模过大。
- **部署**：GitHub Pages 工作流已就位（`.github/workflows/deploy.yml`），但仓库尚未创建，因此还没有线上地址。

## 核心技术

| 层                 | 选型                                                                       |
| ------------------ | -------------------------------------------------------------------------- |
| 构建 / 检查 / 测试 | vp（Vite+）1.3.0，内含 Vitest 5                                            |
| 界面               | React 19 + TypeScript（`strict`）+ Tailwind 3.4 + shadcn/ui（Radix + CVA） |
| 求解内核           | 自研，无第三方数学库                                                       |
| 数值表示           | BigInt 精确有理数（`Frac`），全程不使用浮点                                |
| 算法               | 高斯消元（RREF）、两阶段单纯形（Bland 规则）、分支定界                     |
| 部署               | GitHub Pages + GitHub Actions，`base` 由 `PAGES_BASE_PATH` 注入            |
