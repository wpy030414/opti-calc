# Spec — 结果面板（SolutionPanel）

## 要构建什么

- **目标**：把 `Solution` 翻译成一般人群能看懂、且愿意相信的结论。
- 关键难点不是渲染，而是**失败时说什么**。「无解」「无界」对目标用户是术语，必须翻译成可执行的下一步。

## 行为

### 展示顺序

按「算账的人先看什么」排列，而非按数据结构排列：

```
诊断横幅（无解 / 无界 / 未能求解）   ← 永远置顶，它是用户下一步的唯一线索
  ↓
目标值卡片（最大值 / 最小值）        ← 花钱多少、收益多少，这是用户真正要的答案
  ↓
各变量取值表                        ← 具体怎么安排
  ↓
约束核对表                          ← 让用户能自己验证答案合理
  ↓
需要注意（warnings）
  ↓
规模统计（变量数 / 约束数 / 整数变量数 / 搜索节点数）
```

### 诊断文案

| 状态                              | 必须传达                                                                                                                        |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `optimal`                         | 「已求解」+「找到满足全部条件的答案」                                                                                           |
| `optimal` 且 `approximation` 存在 | 「近似解」+「非凸问题无法精确求解，以下为带损失率保证的近似最优解」；目标值前加「≈」并显示损失率上界                            |
| `infeasible`                      | 原因 + 可操作建议：「试着放宽某个上限、降低某个下限，或检查是否把不等号写反了」                                                 |
| `unbounded`                       | 把术语翻译成人话：「目标值可以无限增大，说明还缺一个限制条件」+「现实中总会有预算、库存或时间上限，把它写成一条 `<=` 约束即可」 |
| `degenerate`                      | 原因（规模超限等），不假装求解成功                                                                                              |

### 数值展示

- 有限小数直接给小数（`5.47`、`131.28`）。
- 无限小数给「分数 ≈ 小数」（`119/240 ≈ 0.495833`）——算账场景里用户需要看到精确分数才敢信这个数。
- 整数不显示小数部分。
- 变量表按 `Solution.varOrder`（模型中首次出现的次序）排列，不用字母序——用户写下条件的顺序就是他期望看到答案的顺序。
- `Solution.approximation` 存在时，目标值前加「≈」，并显示「相对损失率不超过 X%」；这是可证明的差距上界，不能省略。

### 约束核对表

- 每条约束显示：标签（无名则显示「第 N 行」）、余量（`left − right`）、状态徽标。
- 状态区分三档：`取等`（余量为 0，约束刚好用满）、`满足`（有余量）、`违反`（红色）。
- 「取等」单独标出是有意义的：它告诉用户哪个约束是瓶颈，放松它才能改善目标。

## 输入 / 输出

- **输入**：`solution: Solution | null`、`objectiveLabel: string`（由 `App` 依 `objectiveSense` 决定「最大值」/「最小值」/「目标值」）。
- **输出**：纯展示组件，无内部状态、无副作用、不回调。

## 约束

1. **不做二次求解**：面板只渲染 `Solution`，不重新解析模型、不自己算目标值。所有数值来自内核。
2. **不吞掉 warnings**：`warnings` 全部渲染，包括「解不唯一，下面是其中一个解」这类可能让用户误判的提示。
3. **不美化失败**：infeasible / unbounded / degenerate 一律不给变量表，避免用户把无意义的数字当成答案。
4. 长列表用 `ScrollArea` 限高滚动，不把页面撑长。

## 边界条件

- **`solution === null`**（空模型）：显示「在左侧写下条件后自动求解」，不显示任何诊断。
- **无目标函数**：不显示目标值卡片，只显示变量表。
- **`values` 为空**（求解失败）：显示「没有待求的未知量」而非空白。
- **`varOrder` 与 `values` 不一致**：以 `varOrder` 为主序，再补上 `values` 里存在但 `varOrder` 漏掉的变量，防止漏显示。
- **`constraintReport` 为空或缺失**：整块隐藏，不显示空表格。
- **`warnings` 为空**：整块隐藏。
- **`lpNodes === 1`**（未走分支定界）：不显示「搜索节点」，该数字对纯 LP 无意义。
- **超大数值**：`Frac` 的 BigInt 位数可能很长，展示层不做截断（截断即失真），由容器 `overflow` 处理。

## 验收标准

- [x] 默认算例（钱不够时要等多久）求解后显示「已求解」、「份数」、「等待分钟」、「29.75」、「约束核对」
- [x] 无解模型（`x = 10` 且 `x <= 5`）显示「无解」与「放宽」建议
- [x] 乘积变量缺少边界时（`收益 = x * y` 且无上界）显示「参与乘积」与「上界」提示
- [x] 连续相乘的近似解显示「近似」与「损失率」
- [x] 切换到 `x + y = 10 / x - y = 4` 后显示解 7 与 3
- [x] 内核层验收见 `docs/specs/module-solver.md`（约束核对表的余量计算由内核 `reportConstraints` 负责）

### 尚未自动化验收的项

- 「无界」文案的完整渲染路径——当前组件测试覆盖了 infeasible 与乘积缺边界提示，unbounded 在内核层（`tests/unit/lp.test.ts`）已验证状态与原因，但未验证面板文案。
- 「取等 / 满足 / 违反」三档徽标的视觉区分。
- 无限小数的「分数 ≈ 小数」双显示形式在窄屏下的换行表现。

## 完成定义

- 用户看到答案后不需要相信黑箱：约束核对表让他能自行验证。
- 求解失败时用户知道**下一步改什么**，而不是只被告知「无解」。
- 解不唯一时用户不会把「其中一个解」误当成「唯一答案」。
